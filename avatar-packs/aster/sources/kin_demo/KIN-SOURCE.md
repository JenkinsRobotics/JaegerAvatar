## Implementation

`public/js/rig.js` combines spring-driven facial expressions and input with authored full-body motion. `motion.js` uses timed pose keys and monotone cubic interpolation, with anticipation, held poses, and recovery. Authored skeletal curves bypass the extra spring layer so landing/contact timing is preserved. Emotion, pointer gaze, breathing, blinking, typing response, camera input, and speech still blend into the performance. Eyes respond first; head rotation follows; the torso follows later. Frame integration uses bounded substeps so a suspended tab does not destabilize the rig. The spin retains its final heading and can be interrupted without winding backwards. It pivots around the support foot and changes arm reach through the turn. Hand targets are normalized to limb length. Dance steps shift the pelvis onto the support leg before the other foot travels; planted targets stay fixed as the pelvis moves. Pelvis height adjusts to keep leg IK within reach. The hop uses a 9.81 m/s² ballistic arc, anticipation, and landing compression. Idle breathing moves the chest rather than lifting the entire body, and repetitive automatic nodding was removed. This is authored animation with contact constraints, not a full rigid-body physics simulation or motion capture.

`public/js/eyes.js` implements Momo’s eye performance: 64-point contours morph continuously between rounded eyes, curved lids, hearts, stars, and chevrons. Shape, gaze, color, independent blinks, and secondary marks have damped transitions. Reactions use anticipation and timed holds; subtle gaze shifts pause between glances. Speech energy adds a small eye response. The display updates at the render rate, with mipmap generation disabled. The shell, camera, and world transform ignore body-gesture channels, including spin and jump. Only explicit view controls rotate the object. All face state is serialized through the existing output relay.

`public/js/renderer.js` draws both companions with locally stored Three.js. Momo uses original rounded geometry, a recessed dark display, ceramic material, rubber feet, and a canvas eye texture. The earlier Pip study remains as source geometry and archived recordings. Aster uses real VRM joints, analytic two-bone arm and leg IK, planted feet, weight shifts, articulated fingers, five vowel morphs, MToon shading, and spring-bone hair. The 12 fps option holds Aster’s pose while hair physics updates every rendered frame.

Momo’s display animates at 60 Hz on this machine; the body stays fixed. Face tracking allows only one in-flight frame, preventing a growing inference queue. The output relay posts at up to 30 Hz only when output viewers exist. Device pixel ratio is capped at 1.75 to limit GPU load. All browser dependencies are local, and a content security policy blocks external connections.

`public/js/parser.js` incrementally accepts inline expression and gesture tags, including tags split at any stream boundary, aliases, unknown bracketed prose, singing regions, and hidden thinking markers. Text is placed into the UI with `textContent`. Special-token markers are stripped on the server before user text enters Gemma’s raw prompt.

`server.py` uses a loopback-only standard-library HTTP server. It streams Gemma completions as NDJSON; browser sentence buffering starts voice synthesis before the full reply finishes. The raw prompt follows the current Gemma 4 `<|turn>` template and prefills the assistant with `[`. No browser speech-recognition service or macOS `say` is used.

Two persistent Piper models stay loaded in memory. `public/js/audio.js` schedules synthesized WAV clips on an AudioContext timeline and overlaps preparation of the next clip with current playback. `audio_analysis.py` derives RMS energy and LPC formants from each real waveform, maps them to approximate vowel poses, and closes the mouth in silence. Animation samples the waveform **55 ms ahead** of its scheduled playback. This is a responsive animation heuristic, not a phoneme recognizer.

The original additive formant instrument remains as the legacy `/api/vocal` fallback. Voice lab offers the SoulX reference-conditioned singer and the earlier Kokoro score adapter; chat-triggered singing still uses the Kokoro adapter. ACE-Step remains an explicit backend-only option. Chatterbox supports laughter/chuckle tags in speech. SoulX uses a synthetic reference from the selected Kokoro speaker but does not guarantee the same perceived vocalist. Singing-user-reference uploads and streaming singing are not implemented.

## Limits, honestly

- This is a substantially more expressive procedural VTuber demo. Aster is a usable stylized VRM performer, **not a bespoke high-end anime character or Guilty Gear-quality rendering**. Its silhouette, clothing, and expressive range are limited by the source asset.
- The VRM has no jaw bone; it uses mouth morphs. Ink comes from MToon outlines, not a complete depth/ID/normal compositor. Some hair seams and articulated-arm poses remain visibly CG.
- The two characters share conversational state, but Momo uses an original eye display and Aster uses morph shapes. Blush/tint channels are visibly realized on Momo; the sample does not supply equivalent anime morphs.
- Audio generation, scheduling, waveform analysis, and transcription were verified. **Sound was not judged by ear**, and real camera/microphone capture was not exercised. Permission, actual face-tracking quality, and device behavior still need a user check.
- Stepped animation, desktop views, and exports were tested. Mobile layout has responsive CSS but was not device-tested. There is no WebXR/headset mode.
- The built-in server is for a single local user, not public hosting. Conversation history is session-only, with the last ten turns sent to Gemma. Long-running/multi-user stress testing was not performed.

All newly created dependencies, assets, recordings, exports, and caches remain inside `local-avatar-demo/`.
